| Column | Observed level |

## 5. Kootaj Identification

### File 1 — **CONFIRMED**
- Column: `شماره کوتاژ`
- Format: mostly Excel number; some Latin digit text; lengths 5–6
- Master sheet: **624 rows → 598 unique Kootajs**; **15 Kootajs with multiple item rows**
- Cause of repeats: different `کد تعرفه` + `شرح کالا` + `وزن` (same قبض، same values/rights)
- Example: Kootaj `202770` → 8 item rows, one قبض `526327`, rial `5,278,362,660` repeated on every row

### File 2 — **CONFIRMED**
- No `شماره کوتاژ` header
- Use **`شماره مجوز بارگیری`** as Kootaj key for this export shape
- 607 rows → **576 unique** keys; **19 multi-item groups**
- Overlap with File 1: **526** existing; **50** new candidates
- Example new: `208856`, `210346` (also referenced in File 3)

### File 3 — **CONFIRMED**
- No Kootaj column
- Extract from `توضیحات` only
- Pattern 100% of rows: `اظهارنامه متروکه به شماره کوتاژ {digits}`
- 86 rows → 77 unique Kootajs; 75 in File 1; 2 only after File 2 (`208856`, `210346`)

**Parent key = Kootaj.** Row/item multiplicity must not create multiple parents. **CONFIRMED**

## 7. File 2 Aggregation Rules

Derived from multi-row groups (e.g. 128710×4, 202770×8). **Do not invent; measured from data.**

| Field | Level | If multiple rows | Rule | Confidence |
|-------|-------|------------------|------|------------|
| شماره مجوز بارگیری | Kootaj key | Same | Use as Kootaj id | **CONFIRMED** |
| زمان کوتاژ | Kootaj | Same | FIRST | **CONFIRMED** |
| ارزش ریالی اظهارنامه | Kootaj total | Identical on every row | **FIRST / ANY — never SUM** | **CONFIRMED** |
| ارزش ارزی اظهارنامه | Kootaj total | Identical on every row | **FIRST / ANY — never SUM** | **CONFIRMED** |
| نرخ ارز / نوع ارز | Kootaj | Same | FIRST | **CONFIRMED** |
| نام/کدینگ صاحب/کارگزار/اظهارکننده | Kootaj | Same | FIRST | **CONFIRMED** |
| شماره قبض انبار | Receipt | Same in sample | FIRST → receipt entity | **CONFIRMED** |
| وزن ناخالص | Item | Differs | **Keep detail; parent total = SUM(details)** | **CONFIRMED** |
| وزن خالص | Item | Differs | Same as weight | **CONFIRMED** |
| تعداد بسته | Item | Usually differs | **Keep detail; may SUM for total packages** | **CONFIRMED** |
| نام کالا | Item | Differs | Keep detail | **CONFIRMED** |
| کد اچ اس کالا | Item | Differs | Keep detail | **CONFIRMED** |
| نوع بسته | Item | Can differ | Keep detail | **CONFIRMED** |
| کشور سازنده | Item (often) | Can differ | Keep detail | **CONFIRMED** |
| بیمه / کرایه | Unclear | Almost always same; rare noise | FIRST; do not SUM | **PROBABLE** |
| حقوق استنباطی | — | Absent in File 2 | N/A | **CONFIRMED** |

**Anti-pattern:** summing ارزش ریالی/ارزی across item rows multiplies the declaration total by item count (e.g. 4× for 128710).

One anomaly group (`زمان` collision `1403/3/20 21:1:13` vs `21:11:3`) looks like datetime formatting / distinct declarations — treat conflicting parent fields as validation errors, not silent merge. **PROBABLE**

## 8. New Kootaj Import Logic

```
FUNCTION import_file2(rows):
  NORMALIZE each row
  GROUP rows BY normalize(شماره مجوز بارگیری)   # effective Kootaj

  FOR EACH group IN groups:
    kootaj_id = group.key

    IF kootaj_id exists in master_database:
      SKIP   # no insert, no update, no overwrite
      CONTINUE

    ELSE:
      parent = extract_kootaj_level_fields(group)
        # FIRST of: زمان کوتاژ, parties, currency, rate,
        # ارزش ریالی, ارزش ارزی, countries (stable ones), ثبت سفارش
        # ارزش* = FIRST/ANY, never SUM

      receipts = distinct warehouse receipts in group
      items = each row as item detail
        # نام کالا, HS, weights, تعداد بسته, نوع بسته, کشور سازنده
        # link to receipt

      INSERT kootaj parent
      INSERT receipts
      INSERT items

      # Do NOT invent حقوق استنباطی / وضعیت / letter from File 2
```

**CONFIRMED** against business rules + measured keys.

Expected on this sample: skip ~526, insert ~50 new.

## 9. File 3 Letter Processing

```
FOR EACH automation row:
  letter_system_id = شناسه نامه
  letter_number    = شماره ثبت          # populated 77/86; وارده empty in sample
  letter_date      = تاریخ ثبت if present else تاریخ تهیه
  description      = توضیحات
  kootaj_id        = extract_kootaj(description)

  IF kootaj_id is null:
    → Unmatched queue (extraction failed)

  ELSE IF kootaj not in database:
    → Unmatched queue   # DO NOT auto-create Kootaj

  ELSE IF kootaj already has letter:
    → Conflict queue (business: max one letter)

  ELSE:
    Attach letter fields to Kootaj
```

**Multiple File 3 rows per Kootaj (6 Kootajs, e.g. 202062×3):**  
In every multi case, **exactly one row has `شماره ثبت`**. **PROBABLE** rule: prefer the row with non-empty `شماره ثبت`; ignore draft rows without it; if still >1, conflict queue.

## 10. Kootaj Extraction From Description

**Deterministic:** **CONFIRMED** (86/86 labeled extract; 0 failures in sample)

**Sole observed pattern:**
```text
اظهارنامه متروکه به شماره کوتاژ <digits>
```

**Primary regex:**
```regex
شماره\s*کوتاژ\s*[:：]?\s*([0-9۰-۹٠-٩]{4,10})
```
Then normalize digits.

**Fallback (only if labeled pattern missing):** **PROBABLE** / unused in this sample  
`کوتاژ\s*[:：]?\s*([0-9۰-۹٠-٩]{4,10})`

**Do not use** bare 5–7 digit standalone matching (false positives).

**Edge cases:** empty description; multiple Kootaj mentions; format drift; unmatched Kootaj (create queue, not parent). In sample: empty=0, multi-candidate=0, unmatched vs File1-only=2 (exist in File 2).

## 11. Data Normalization Rules

| Rule | Detail | Confidence |
|------|--------|------------|
| Persian digits ۰-۹ → 0-9 | Apply before match | **CONFIRMED** (needed; none in current Kootaj cols) |
| Arabic-Indic ٠-٩ → 0-9 | Same | **CONFIRMED** (defensive) |
| Trim whitespace | Always | **CONFIRMED** |
| Strip non-digits for Kootaj compare | After digit fold | **CONFIRMED** |
| Strip leading zeros | `012345` → `12345` | **CONFIRMED** |
| Excel numeric | `Math.trunc` / integer string | **CONFIRMED** (File1 mostly numeric) |
| Comma thousands | Remove before parse (`5,278,362,660`) | **CONFIRMED** |
| Warehouse IDs | Alphanumeric possible (`106502A`, `147371E`); normalize carefully — not pure int | **CONFIRMED** |
| Datetime | Normalize Shamsi `y/m/d h:m:s` with zero-padding for compare | **CONFIRMED** |
| Letter `شماره ثبت` | Strip invisible chars; keep `year/number` shape | **CONFIRMED** |
| Arabic ي/ك vs Persian ی/ک | Normalize in descriptive text if matching descriptions | **PROBABLE** |

Goal: `123456` / `۱۲۳۴۵۶` / numeric `123456` → same Kootaj. **CONFIRMED** as requirement; implementable deterministically.

## 13. Complete Deterministic Processing Pipeline

### A. Initial Import (File 1)
```
File 1 → read sheet «متروکه کلی» only
→ normalize Kootaj / numbers / dates
→ group by Kootaj
→ INSERT Kootaj parent (FIRST of repeated totals/rights/status)
→ INSERT receipt(s)
→ INSERT item rows (tariff, description, weight)
→ do not create letters
```

### B. New Data Import (File 2)
```
File 2 → normalize
→ group by normalize(شماره مجوز بارگیری)
→ IF exists → SKIP (insert-only)
→ IF new → CREATE parent + receipts + items
→ never overwrite master fields
```

### C. Automation Import (File 3)
```
File 3 → read شناسه نامه / شماره ثبت / تاریخ‌ها / توضیحات
→ extract Kootaj from توضیحات (regex)
→ find Kootaj
→ IF not found → Unmatched queue
→ prefer row with شماره ثبت when duplicates exist
→ IF found and no letter → attach letter fields
→ IF found and letter exists → Conflict queue
```

**Order matters:** run File 2 before File 3 so new Kootajs like `208856` / `210346` can receive letters. **CONFIRMED** by cross-file evidence.

## 14. Validation / Error Handling

| Case | Action |
|------|--------|
| Duplicate Kootaj on File 2 insert | Skip (expected) |
| File 2 group with conflicting parent totals | Quarantine group; do not insert | 
| Missing/invalid Kootaj key | Reject row → error queue |
| File 3 extraction failure | Unmatched queue |
| File 3 Kootaj not in DB | Unmatched queue (no auto-create) |
| File 3 multiple letters with `شماره ثبت` | Conflict queue |
| Warehouse ID non-numeric | Store as text |
| Re-import File 1 | Idempotent by Kootaj (+ item fingerprint) |
| Partition sheets of File 1 | Do not double-import |

### Bottom line

Kootaj is the parent; File 1/2 multi-rows are item details with **repeated declaration totals** (never sum value/duties); File 2 is insert-only using **`شماره مجوز بارگیری`** as Kootaj; File 3 attaches at most one letter via regex on Description plus dedicated `شماره ثبت`/`تاریخ` fields; the whole path is **deterministic without AI**.
